# P8 / E3: usage redistribution (`+us`) and the stack test over the OFF switches

*2026-10-24. IMPROVEMENTS.md P8 and E3. Live model `pathA-v0.3+mf+ep+ms+p2+rx+rb+tr`. Runs on the
Mac scratch dir `~/Developer/courtside-compute/p8e3/` (code tree = HEAD 91d131d + this change;
rows and JSON in `out/`, logs in `logs/`). Script: `research/p8_e3_eval.py`.*

## Plain-language summary

- **P8 (`+us`).** When a teammate is out, the model used to raise the per-minute rates of the
  rest of the team only if one of the team's two stars was out, and by one number per role. The
  new switch uses the already-built usage v1 instead: each absent regular (10+ mpg) moves usage
  to each teammate according to their role, position and the pair's own on/off history. It is
  built behind `COURTSIDE_USAGE` (`+us`), default OFF, and OFF is bit-identical.
- **Result:** better on all four backtest seasons (DK CRPS z −1.8 / −3.3 harness, −2.7 / −4.2
  RotoGuru, two-way SEs), and the value-ranking metric improves on every set (z +1.0 to +4.9).
  On the 2025-26 live slice it is neutral (z +0.3 lock−45, −0.6 lock−10). The gain sits in games
  where a star sits (where the old bump fired, usage v1 distributes better); games where only
  non-stars sit gain on RotoGuru but not on 2023-25.
- **Recommendation for `+us`:** do not ship yet; add it as a live shadow (registry entry below).
  The live slice, the only untouched set, does not confirm it.
- **E3 (stack test).** Forward selection over the OFF player-side switches on the 2023-24 /
  2024-25 harness picks `+us`, then `+c1r` (copula v1 retune), then stops (`+mr` −1.9 z, the rest
  |z| < 1.3 at every step; `+rr` is worse). Confirmed on live / live10 / RotoGuru: **`+c1r` holds
  on every set, most strongly on the untouched 2025-26 slice (z −5.6 / −4.0)**; `+us` adds nothing
  on the slice on top of it. Two lock-only switches tested on the slice alone: `+pq` (lock−10)
  −2.6 z, `+gd` neutral. **Ranked: ship `+c1r` (owner), ship `+pq` (owner), shadow `+us`; leave
  the rest OFF; retire `+rr`.**
- **Finding on the way:** the live / live10 numbers in the ledger for `+rx`, `+rb`, `+tr`, `+ep`,
  `+ms` and `+rw` were run in scratch data dirs with no ESPN scoreboard archive and no 2025-26
  `games` rows, so every slice game ran at the 19:30 ET default tip (the 2026-10-22 "slice
  artifact"). The paired differences are still like-for-like, but on a distorted information
  set. This doc's live runs use the real tips (`raw/espn_odds/scoreboard`, 104/104 slice dates).

## 1. P8: what was built

| piece | where |

| tests | `tests/test_usage_switch.py` (8); `COURTSIDE_USAGE=0` pinned in `tests/conftest.py` |

The factor for player i in a sim is exp(clip(Σ over absent regulars j of L[j, i], ±0.4)), per DK
stat (usage v1, `docs/PLAYERS.md` T2.3: a tier × position-pair prior on j's share of the team's
production, a stint on/off layer, and a box with/without layer, each shrunk). It replaces the tier
bump for every player of the team (the bump is not applied on top). Reconciliation still pins the
team total to the implied total, so the switch moves points between teammates.

**OFF is bit-identical.**
- `id_driver` (live stack, `+us` OFF), HEAD 91d131d tree vs the working tree: `project_historical`
  2024-01-10 and 2020-01-15 and `project_slate` 154575 at 2026-10-20T22:15Z: players, stats,
  sims (5.05M fp values) and meta identical.
- The whole-season OFF harness rows of this tree (2023-24, 2024-25, 2019-20 avail, 38-34k rows ×
  39 columns) equal the `p46` rows (HEAD-equivalent tree) exactly.
- `+c1r` ON (v1 sim path, where the hook also sits), HEAD vs the working tree, `project_historical`
  2024-01-10: identical (1.23M fp values).
- Unit: `tests/test_usage_switch.py` (OFF leaves `TeamSpec.usage` None; all-zero factors equal OFF
  without a star absence; a positive factor moves share; the factor applies only in sims where
  the teammate sits; the copula v1 path reads the same factors; params keyed by rate state;
  non-regulars carry no factor). The existing
  copula / pipeline goldens pass unchanged.

**Decision:** keep OFF; run as a live shadow (E1 is the confirmatory set). The gain is consistent

for tuning, does not confirm it.

## 4b. Tip times in the earlier live-slice runs

`availability.day_games` takes tips from the `games` table, else the ESPN scoreboard archive, else
19:30 ET. The scratch data dirs of `rx`, `rb`, `tr`, `ep` and `p46` (`+ms`, `+rw`) had neither
(no 2025-26 `games` rows, `raw/` without `espn_odds`), so their live / live10 rows ran every game
at 19:30 ET. Compared with this doc's real-tip OFF rows (same code, same seeds), only 19 % / 37 %
of means are equal and the OFF CRPS is 5.69 / 5.59 vs 5.64 / 5.53 with real tips. The paired
ON−OFF numbers in the ledger compare like with like, so the decisions stand, but the live
evidence for those six switches was on a distorted information set. Fix for future scratch dirs:
copy `raw/espn_odds/scoreboard` (6.7 MB, e.g. from `courtside-compute/pq/raw/`).
