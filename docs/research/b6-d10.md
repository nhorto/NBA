## 0. Summary

- **B6:** built behind `COURTSIDE_SD_CPT` (`+cpt` on the ownership and field versions of Showdown
  slates; default OFF). OFF is bit-identical to HEAD. **The accuracy check cannot run yet.** No
  Showdown standings have been uploaded: all 4 uploads are slate 154575 (Classic), and the owner's
  2026 entry history is Classic only. There is no public Showdown ownership anywhere in our data
  (research/, docs/research, var/raw: the only %Drafted files are those 4 uploads). The evaluator
  is ready: run `courtside dfs showdown-own` after the first Showdown standings upload. Keep OFF
  until then.
- **What the current proxy does (measured, 15 stored Showdown slates):** the §9 worry about the
  salary shadow price is not the problem. λ is about zero, and where negative it favours expensive
  captains (as §9 said). The problem is that OFF captains cheap value players about as readily as
  stars (§1).
- **D10:** the contest builder works for Showdown end to end. In-model, on held-out sims with a
  fresh field, it beats Top N by mean on expected payout: **1.48× at N = 20 (SE 0.15), 14 of 15
  slates**. That holds with the B6 field. It cashes and reaches the top 1 % somewhat less often.
  The Showdown slate page and builder page now point Showdown users at the builder with that
  trade-off stated. This is display only, so no switch.

## 1. B6: measuring the current proxy

`research/b6_showdown_own.py measure`. Every stored Showdown slate with a run (15), using its
reference run (lock10, else lock45) and inputs as the public saw them at lock. Large-GPP
archetype; small GPP is within 0.01 everywhere. Values are means over slates (SE over slates).

| CPT ownership of the best public projection | 0.160 (0.014) | 0.179 (0.014) |
| CPT ownership of the top-3 projections | 0.419 (0.031) | 0.495 (0.029) |

| same, at λ = 0 (utility alone) | $7,301; spend 0.949 of cap | $8,806; spend 0.982 |

- **The λ question (§9 correction):** with the UTIL utility alone the field underspends (0.949 of
  the cap vs SPEND 0.997). λ is therefore negative on most slates and tilts captains toward
  expensive players: +$545 CPT mean salary vs λ = 0. That is the direction §9 predicted, not the
  first review's "cheaper captains". But |λ| is small and not distinguishable from 0 across
  slates (−0.08 ± 0.06).
- **The real defect:** with one utility for both columns, a player's CPT share of his own
  ownership is close to proportional (1/6 = 0.167) for everyone. Value plays are captained almost
  as often per unit of ownership as stars: 0.142 vs 0.174. Example, slate 154826: OG Anunoby
  ($6,200, projected 32.3, the 7th-best projection) was the most-owned captain at 16.9 %. Public
  Showdown play is the opposite: captains go to the stars, and value plays fill UTIL.

### The captain term (ON)

`field.cpt_utility`, used for the CPT column only; UTIL keeps the old utility. Hand-set prior
(`field.CPT_PARAMS`):

    u_cpt = conc * ( 0.40 z(value) + 0.70 z(pub) + 3.0 log(pub / pub_max)
                     + b_total z(total) + b_repl repl + b_q q + b_bench bench )

- **Star term:** the CPT weight carries (pub / best pub)^(conc·3). This is a smooth version of
  "public-projection rank". A hard rank (first try, −log rank) put 28 % vs 11 % CPT on two
  players projected 41.1 and 41.0 (slate 154826), so it was replaced.
- **Value term:** 0.40 at CPT vs 1.10 at UTIL.
- **Other terms:** Q, bench, replacement and team-total terms are shared with UTIL. The Sinkhorn
  allocation, row cap and shadow price are unchanged, so Σ own = 600 %, the CPT column sums to
  100 %, and no player exceeds the cap.
- **Fit:** none. The prior's targets are qualitative public-DFS facts: captains concentrate on
  the best projections, and value plays are rarely captained. Gate the weights on uploaded
  Showdown standings.
- **Other code changes:** `fit_from_uploads` now compares a Showdown contest on the UTIL column
  (Showdown uploads store UTIL %Drafted; the CPT % is in the upload's `detail`). Before, it would
  have compared total ownership with UTIL-only %Drafted. No Showdown uploads exist, so nothing
  changes today.

### Acceptance, when data exists

`courtside dfs showdown-own` (`showdown.ownership_eval`) reports, for every uploaded Showdown
contest:
- inputs rebuilt at lock;
- MAE (pp) and rank correlation per slot (CPT, UTIL) for OFF and ON, plus the ON − OFF paired
  difference;
- MAE SEs two-way clustered by slate × player (`metrics.paired_cluster2`; iid with one slate),
  and rank-correlation SEs by a player bootstrap within contests.

The pipeline was smoke-tested on the scratch DB with two synthetic uploads, then removed. Ship
bar: CPT MAE lower by > 2 SE, no worse UTIL MAE, CPT rank correlation not lower, on ≥ 3 Showdown
contests from ≥ 2 slates.

## 2. D10: the contest builder on Showdown

### End to end (scratch DB, slate 155558, $60K Fadeaway, 4,705 entries)

`d10_showdown_replay.py e2e` ran `build_for_slate` → `save` → `load` → DK CSV → builder page
view model, with N = 20 and the shipped settings (`+split-gs+obj-blend+xf2`). It took 13 s.
- The CSV header is `CPT,UTIL,UTIL,UTIL,UTIL,UTIL`.
- The CPT column uses the CPT draftable id (Doncic CPT, $19,800).
- All 20 lineups pass the rule checks: six distinct players, ≥ 2 teams, ≤ $50,000, CPT salary
  1.5×.

No Showdown build had ever been run in prod (`dfs_portfolios` has none on Showdown slates).

### Replay: builder vs Top N by mean

`d10_showdown_replay.py replay --ns 1 5 20`.
- **Slates:** the 15 stored Showdown slates with sims, each at its reference run (lock10 on 14,
  lock45 on 155310).
- **Contests:** the slate's largest captured GPP on 11 slates (fees $10–18, 980–13,071 entries);
  a preset GPP of the median captured shape (3,137 entries, $15) on the other 4.
- **Builds:** shipped builder settings (split `gs`, objective `blend`, xf-v2, ownership OFF).
  Top N = the builder's own baseline (the first N `topn.top_n` lineups by mean, min different 1,
  the lineups the slate page lists).
- **Scoring:** both sets scored jointly on the 11,250 held-out report rows (R) of 25,000 sims.
  "Fresh" = a new truth-noise draw on R and a new field sample (new seed), so neither the sims nor
  the field sample that picked the set scores it.

Expected payout, builder / Top N. "Ratio" is the pooled ratio of mean payout per fee, with a
delta-method SE over slates.

| N | evaluation | ratio (SE) | median slate | slates builder better | Δ P(any top 1 %) (SE) | Δ P(any cash) (SE) |
|---|---|---|---|---|---|---|
| 1 | R, build's field | 3.72 (0.94) | 2.93 | 14/15 | +0.005 (0.003) | −0.117 (0.018) |
| 1 | R fresh, OFF field | 3.60 (0.87) | 3.23 | 13/15 | +0.005 (0.004) | −0.118 (0.019) |
| 1 | R fresh, `+cpt` field | 4.10 (0.98) | 3.36 | 13/15 | +0.005 (0.004) | −0.118 (0.019) |
| 5 | R, build's field | 1.78 (0.28) | 1.77 | 15/15 | −0.035 (0.017) | −0.108 (0.026) |
| 5 | R fresh, OFF field | 1.99 (0.37) | 1.75 | 13/15 | −0.034 (0.016) | −0.109 (0.026) |
| 5 | R fresh, `+cpt` field | 1.91 (0.38) | 1.56 | 13/15 | −0.035 (0.016) | −0.109 (0.026) |
| 20 | R, build's field | 1.47 (0.13) | 1.50 | 14/15 | −0.044 (0.021) | −0.037 (0.013) |
| 20 | R fresh, OFF field | **1.48 (0.15)** | 1.43 | 14/15 | −0.039 (0.020) | −0.037 (0.013) |
| 20 | R fresh, `+cpt` field | 1.49 (0.15) | 1.42 | 14/15 | −0.041 (0.020) | −0.036 (0.013) |

- **Δ columns:** builder minus Top N, mean over slates with the SE over slates. The SE from sims
  alone is about 10× smaller (e.g. N = 20 any-top-1 % 0.0015).
- **Mean per-entry P(top 1 %), builder − Top N:** +0.005 / −0.009 / −0.004 at N = 1 / 5 / 20
  (SE over slates 0.004 / 0.004 / 0.002).
- **Sets:** the builder never repeated the Top N set (1 of 15 at N = 1). It used more captains:
  6.8 vs 5.1 distinct at N = 20, 3.5 vs 2.7 at N = 5. It shared 2.2 of 20 lineups with Top N.
- **Runtime:** 6–9 s per build (vs ~200 s for a 150-entry Classic build).

**Reading.** In our model the builder's expected payout is clearly higher at every N, and the
result does not depend on how captains are owned (the `+cpt` field gives the same ordering). The
trade is the one the objective makes: it gives up frequent small cashes, and at N ≥ 5 some top-1 %
finishes, for 1st-place equity. Top N stacks near-identical chalk lineups that the modelled field
duplicates and that bust together.

**Absolute levels are not credible.** In-model ROIs are +240 % (Top N) and +400 % (builder) at
N = 20 against the modelled field. The HANDOFF already notes that the modelled field is far weaker
than a real DK field, and these Showdown fields are hand-set proxies with no Showdown calibration.
Only the comparison is used.

**Actual box scores** (one draw per slate, scored against the fresh modelled field; still not
the real field):
- **N = 20:** builder $42,883 vs Top N $3,381 on $4,580 of fees. Three builder 1st places
  (155486, 155552, 155558) carry it. Per slate the builder was ahead on 7 and behind on 8. ROI
  difference +8.8 (SE 5.4).
- **N = 5:** $1,192 vs $1,144 (+0.06, SE 0.41).
- **N = 1:** $422 vs $125 (+1.27, SE 1.49).
- **Cashes:** about the same counts (N = 20: 14 vs 13 slates with any cash; N = 1: 3 vs 5).

This is consistent with the in-model picture (lumpy, top-heavy) but far too noisy to confirm it.
